--- 10. patch a/b/c 적용 (사용자가 node-a SSM에서 직접 실행) ---
================================================================================

사용자가 node-a SSM(`sudo -i`)에서 재개 절차의 patch a(Calico ipPool
encapsulation=VXLAN)/b(felixconfiguration vxlanPort=4790)/c(libvirt helm upgrade
listen_address=0.0.0.0)를 순서대로 실행. a/b는 즉시 반영, c의 DaemonSet rollout이
"1 out of 2 new pods have been updated"에서 정지.

$ kubectl get pods -n openstack | grep neutron-ovs
  neutron-ovs-agent-default-kgm8k   1/1  Running            1 (23m ago)   54m
  neutron-ovs-agent-default-ss94v   0/1  CrashLoopBackOff   10 (3m17s ago) 33m

-> ss94v는 patch 적용 이전 타이밍에 이미 떠 있던 파드(위 섹션 8에서 CrashLoop 상태로
   최초 관측된 바로 그 파드) — 재개 절차에 기록된 "rollout 멈춤 시 CrashLoopBackOff
   파드부터 지워봐라" 팁을 사용자가 직접 적용.

$ kubectl -n openstack delete pod neutron-ovs-agent-default-ss94v
  pod "neutron-ovs-agent-default-ss94v" deleted

$ kubectl -n openstack get pods -l application=neutron,component=neutron-ovs-agent -o wide
  neutron-ovs-agent-default-kgm8k   1/1  Running   1 (26m ago)   58m    10.0.1.4    ip-10-0-1-4
  neutron-ovs-agent-default-rw9sq   1/1  Running   0             2m58s  10.0.1.207  ip-10-0-1-207

$ kubectl -n openstack rollout status ds libvirt-libvirt-default
  Waiting for daemon set "libvirt-libvirt-default" rollout to finish: 1 out of 2 new pods have been updated...
  Waiting for daemon set "libvirt-libvirt-default" rollout to finish: 1 of 2 updated pods are available...
  daemon set "libvirt-libvirt-default" successfully rolled out

-> 삭제 직후 재생성된 파드가 정상화되고, libvirt rollout도 곧바로 이어서 완료됨.
   "새 근본원인 아님, 타이밍 이슈였다"는 재개 절차의 가설이 이번 세션에서 실측으로
   재검증됨(2026-09-17 세션에 이어 두 번째).
