L5 — webhook 리시버 (2026-09-19)
================================================================

전제: L4 완료 상태(qemu-exporter/Prometheus/Alertmanager 배포, threshold 0.005 임시값).
test-vm(1bfa7dda-638f-42a4-b377-287144591b6a)은 이 단계 시작 시 node-b(ip-10-0-1-207)에 위치.

--- 0. 구현: cmd/live-migration-webhook/main.go (신규, qemu-exporter 바이너리와 분리) ---

CLAUDE.md 규칙 준수: 별도 cmd/바이너리, Nova API는 live-migration 트리거 용도로만 사용,
같은 VM에 진행 중인 마이그레이션이 있으면 중복 트리거 방지(in-memory set), 실패는 로그만
남기고 프로세스 계속 동작. stdlib(net/http, encoding/json)만 사용 — gophercloud 등 신규
의존성 추가 안 함(가벼운 프로토타입이라 가능한 범위).

동작: POST /webhook으로 Alertmanager payload 수신 → firing 상태 alert의 instance_uuid
라벨 파싱 → 중복 체크 → Keystone v3 password auth로 토큰 발급 → Nova GET /servers/{id}로
현재 호스트 조회 → NODE_HOSTS(고정 2노드 목록) 중 "다른 쪽"을 목적지로 선택 →
POST /servers/{id}/action {"os-migrateLive": {host, block_migration:true,
disk_over_commit:false}}.

단위테스트: cmd/live-migration-webhook/main_test.go의 TestOtherHost (호스트 선택 분기
로직 — 대소문자 무시 매칭, 알 수 없는 호스트는 빈 문자열).

--- 1. 배포: 컨테이너 레지스트리 없이 node-a에서 직접 빌드·실행 ---

컨테이너 이미지 빌드/푸시할 Docker Hub 계정이 이 세션엔 없어서, node-a에 Go 1.22를
apt로 설치(`golang-go`) 후 바이너리를 직접 빌드해 systemd transient unit으로 구동.
Nova/Keystone은 k8s ClusterIP로 직접 접근(호스트 프로세스라 *.svc.cluster.local DNS는
못 쓰지만, kube-proxy가 ClusterIP 라우팅을 호스트 netns에도 설치하므로 IP 직접 접근은 됨):
  OS_AUTH_URL=http://10.97.0.175:5000/v3       (keystone-api ClusterIP)
  NOVA_URL=http://10.100.145.208:8774/v2.1     (nova-api ClusterIP)
  NODE_HOSTS=ip-10-0-1-4...,ip-10-0-1-207...   (고정 2노드 FQDN)

$ apt-get install -y golang-go   → go1.22.2 설치
$ go build -o live-migration-webhook main.go   (standalone go.mod, go 1.22 — 메인
  프로젝트의 go.mod(go 1.25 툴체인 요구)와 별개로 이 바이너리만 독립 빌드, 툴체인
  자동다운로드 회피)
$ systemd-run --unit=live-migration-webhook --setenv=... /opt/live-migration-webhook/...
  → active (running), :8080 리슨 확인

--- 2. 1차 검증: Alertmanager 없이 synthetic payload로 직접 테스트 ---

--- 3. VM을 node-b로 원위치 (node-a엔 K8s 컨트롤플레인이 있어 cpu-hog 부하를 node-a에

--- 4. Alertmanager → webhook 연결 ---

deploy/monitoring/alertmanager.yaml route.receiver를 live-migration-webhook으로 변경,
webhook_configs.url = http://10.0.1.4:8080/webhook (node-a 사설IP — 호스트 프로세스라
k8s Service가 아니라 IP 직접 지정).

$ kubectl apply -f alertmanager.yaml && kubectl -n monitoring rollout restart deploy/alertmanager
$ curl .../api/v2/status | ... → route.receiver=live-migration-webhook,
  webhook_configs[0].url=<secret>(마스킹, 실제 반영 확인은 동작으로 검증) 확인.

--- 5. 진짜 end-to-end: cpu-hog → Prometheus rule → Alertmanager → webhook → Nova ---

$ kubectl apply -f cpu-hog.yaml; scale --replicas=8; nodeSelector=ip-10-0-1-207
HOG_ON = 2026-09-19T07:11:21Z

폴링 결과:
  07:12:59 — Alertmanager API: alert state=active (VMCPUPressureHigh)
             동시에 server status=MIGRATING (webhook이 이미 트리거함)
  07:12:58 — journalctl: "migrate action accepted ... from_host=ip-10-0-1-207...
             to_host=ip-10-0-1-4..." / "live migration triggered"
             (alert firing과 거의 동시 — Alertmanager group_wait=10s 이후 즉시 POST)
  07:13:20 — openstack server migration list id=4: completed,
             ip-10-0-1-207 → ip-10-0-1-4
  이후 확인: server status=ACTIVE, OS-EXT-SRV-ATTR:host=ip-10-0-1-4 (node-a)

**HOG_ON(07:11:21) → alert firing(~07:12:58, "for: 30s" + group_wait 10s 반영) →
migration 트리거(07:12:58, alert과 사실상 동시) → migration completed(07:13:20) —
부하 시작부터 마이그레이션 완료까지 총 약 119초.**

$ kubectl delete -f cpu-hog.yaml   (HOG_OFF = 2026-09-19T07:13:43Z) — 정리 완료.
